feat(core): Restauración de Servicios, Implementación API Contenido y Hardening de Tests

RESUMEN DE CAMBIOS:
Este commit resuelve la inestabilidad crítica del sistema detectada durante la fase de regresión. Se ha restaurado la funcionalidad CRUD perdida en servicios core, se ha implementado la totalidad de la API de gestión de contenido (LMS) y se ha endurecido la suite de pruebas para garantizar integridad referencial estricta.

DETALLES TÉCNICOS:

1. 🏛️ ARQUITECTURA Y SERVICIOS (Service Layer)
   - CompanyService: Reconstrucción total de la clase. Se restauraron los métodos CRUD (create, update, delete, get) que faltaban, integrando la lógica de Soft Delete (.filter(esta_activo=True)) para evitar "efectos fantasma" en consultas.
   - UserService: Corrección crítica en `create_user`. El servicio ignoraba campos opcionales del Pydantic model. Ahora persiste correctamente: phone, gender, birth_date, city_id y avatar_url.
   - Database (SQLite): Se implementó un Event Listener en `conftest.py` para activar `PRAGMA foreign_keys=ON` en cada conexión. Esto alinea el comportamiento de los tests con PostgreSQL, revelando y previniendo violaciones de integridad que antes pasaban silenciosamente.

2. 🚀 NUEVA API DE CONTENIDO (LMS)
   - Nuevo Router: `app/api/v1/content.py` implementado con 15 endpoints.
   - Módulos: CRUD completo con validación de orden secuencial.
   - Tareas (Tasks): Soporte para tipos 'video', 'quiz', 'pdf', 'text', 'code'.
   - Recursos: Sistema de adjuntos a tareas.
   - Registro: Router integrado en `app/main.py` bajo el prefijo `/api/v1`.

3. 🔧 CORRECCIÓN DE MODELOS Y SCHEMAS (Mapping Fixes)
   - Resolución de Disonancia Cognitiva (DB vs API):
     - Tasks: Conflicto `type` (Pydantic) vs `task_type` (DB) resuelto mediante mapeo manual en la API y validación estricta en Schemas.
     - Resources: Conflicto `title` (API) vs `name` (DB) resuelto agregando `@property title` en el modelo SQLAlchemy `TaskResource` para lectura transparente.
   - Simulaciones: Se endureció `SimulationCreate` forzando `short_description` como campo obligatorio (min_length=1).

4. ✅ SUITE DE PRUEBAS (QA Hardening)
   - Volumen: Aumento de cobertura a ~200 tests (184 passing, resto placeholders).
   - Nuevo Test Suite: `tests/content/test_content_hierarchy.py` (+60 tests) cubriendo la jerarquía Simulación -> Módulo -> Tarea -> Recurso.
   - Refactorización de Fixtures: Se movieron fixtures críticos (`base_simulation`, `base_company`) al alcance de módulo para solucionar errores de visibilidad ("Fixture not found").
   - Integridad de Datos: Se reescribieron los tests antiguos (`test_simulations.py`, `test_simulations_shield.py`) para eliminar IDs hardcodeados (1) y utilizar objetos reales creados en DB, solucionando los `IntegrityError` de FKs.
   - Estandarización: Mensajes de error unificados a inglés ("already exists") en todos los tests de lógica de negocio.
